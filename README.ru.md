Verso это интернет-магазин книг на Django REST Framework и Vue 3. В нём можно
искать книги в каталоге, собирать корзину, оформлять заказ и отменять его, пока
он ещё не обработан. Книгами и заказами сотрудники управляют в админке Django.
По умолчанию интерфейс на английском. В шапке можно выбрать русский,
французский или немецкий, каталог книг тоже переведён.

![Каталог](docs/screenshots/ru/catalog.png)

## Быстрый старт

```bash
docker compose up --build
```

Откройте <http://localhost:8080> и на странице входа нажмите
**«Войти в демо-аккаунт»** или войдите как **demo / demopass123**. У
демо-пользователя уже есть три заказа и несколько книг в корзине. При первом
запуске в базу загружаются 18 классических романов с обложками.

Документация API (Swagger UI) открывается по адресу
<http://localhost:8080/api/docs/>, админка по адресу
<http://localhost:8080/admin/>. Чтобы при старте создался администратор,
задайте `DJANGO_SUPERUSER_USERNAME` и `DJANGO_SUPERUSER_PASSWORD` в `.env`.

Проверить защиту остатков просто. Положите последние экземпляры книги в
корзину в двух браузерах и оформите оба заказа. Второй заказ не пройдёт, а в
сообщении будет написано, сколько экземпляров осталось.

## Кейс

### Задача

Небольшой книжный магазин хочет продавать через интернет. Магазин не должен
продавать больше экземпляров, чем есть на складе, даже если два человека
оформляют заказ одновременно. Старые заказы должны сохранять свои цены после
изменений в каталоге. Сайтом должно быть удобно пользоваться с телефона и на
разных языках.

### Решение

Вся бизнес-логика находится в REST API, приложение на Vue только обращается к
нему. Заказ проходит такие статусы.

| Статус | Кто ставит | Остатки |
|---|---|---|
| **Ожидает** | Оформление заказа | Экземпляры списываются со склада |
| **Оплачен, Отправлен, Доставлен** | Сотрудник в админке | Не меняются |
| **Отменён** | Покупатель, только пока заказ ожидает | Экземпляры возвращаются на склад |

Оформление заказа идёт в одной транзакции. Сначала блокируются строки книг,
потом проверяются остатки.

```python
with transaction.atomic():
    books = {b.id: b for b in Book.objects.select_for_update().filter(id__in=ids)}
    errors = [stock_message(books[i.book_id]) for i in items
              if i.quantity > books[i.book_id].stock]
    if errors:
        raise ValidationError({"detail": _("Not enough stock."), "items": errors})
    order = Order.objects.create(buyer=user)
    ...  # сохранить название и цену, списать остатки, очистить корзину
```

### Инженерные решения

- Оформление и отмена блокируют строки книг через `SELECT … FOR UPDATE`.
  Проверка остатков, их изменение и новый заказ сохраняются в одной
  транзакции, поэтому после неудачной проверки не остаётся недоделанного
  заказа.
- Строка заказа хранит название и цену на момент покупки. Связь с книгой
  сделана через `SET_NULL`, поэтому правка или удаление книги не меняет старые
  заказы.
- Корзина загружается за постоянное число SQL-запросов. Позиции и книги
  приходят одним `JOIN`, переводы ещё одним запросом. Тест считает запросы, и
  проблема N+1 уронит CI.
- Поиск, сортировка, фильтр «в наличии» и номер страницы хранятся в URL.
  Страницей каталога можно поделиться, её можно перезагрузить или вернуться к
  ней кнопкой «назад».
- Когда access-токен истекает, параллельные запросы ждут одно общее
  обновление, а не отправляют каждый своё.
- Обложки демо-книг взяты из Open Library и лежат в репозитории. Книга без
  картинки получает сгенерированную обложку с названием и автором. Файлы
  Swagger UI отдаются локально, так что приложению не нужны CDN.
- Схема OpenAPI 3 генерируется из кода. CI проверяет её и падает на
  предупреждениях.

### Безопасность

- Access-токен JWT живёт 30 минут. Refresh-токен меняется при каждом
  использовании. Если сессию не удаётся обновить, сайт выходит из аккаунта.
- Вход, регистрация и обновление токена по умолчанию ограничены 20 запросами
  в минуту. У анонимных и авторизованных пользователей отдельные лимиты.
- При регистрации пароль проверяется валидаторами Django.
- После входа сайт перенаправляет только на относительные пути этого же
  сайта, поэтому через `?next=` нельзя увести пользователя на чужой домен.
- Пользователь видит только свою корзину и свои заказы. Чужой заказ отдаёт 404.
- Секреты и хосты задаются переменными окружения. `HTTPS=True` включает
  secure-cookies, HSTS и редирект на HTTPS. Заголовок `X-Frame-Options` всегда
  равен `DENY`.

### Локализация

- Языков четыре, английский, русский, французский и немецкий. По умолчанию
  английский, язык браузера специально не учитывается. Переключатель
  EN / RU / FR / DE запоминает выбор в браузере и выставляет `<html lang>`.
- Интерфейс переведён через vue-i18n с правилами множественного числа для
  каждого языка («1 книга, 3 книги, 5 книг», «0 livre, 2 livres»). Тест
  проверяет, что во всех языках одинаковый набор ключей.
- Названия, авторы и описания книг хранятся в `BookTranslation`, по одной
  строке на язык. Если перевода нет, показывается английский текст. Поиск
  работает по всем языкам, а сортировка по названию и автору идёт по переводу.
- Сообщения API переведены через gettext Django. Фронтенд передаёт выбранный
  язык в `Accept-Language`, поэтому сообщение вроде «Осталось только
  2 экземпляра» приходит на языке пользователя и с нужной формой числа. CI
  проверяет, что скомпилированные файлы `.mo` совпадают с файлами `.po`.
- Цены и даты форматируются через `Intl` под выбранный язык.

### Архитектура

```mermaid
flowchart LR
    U[Браузер<br/>Vue 3 SPA] -->|HTTP| N[nginx<br/>статика SPA и reverse proxy]
    N -->|/api, /admin, /static| G[gunicorn<br/>Django и DRF]
    N -->|/media| M[(Volume<br/>с обложками)]
    G --> P[(PostgreSQL)]
    G --> M
```

SPA и API работают на одном origin, поэтому в продакшене нет CORS, а фронтенд
использует относительные URL. В разработке те же пути перенаправляет на
`runserver` сервер Vite.

| Модуль | Что делает |
|---|---|
| `backend/main/views.py` | Каталог, авторизация, корзина, оформление, заказы, отмена |
| `backend/main/serializers.py` | Формат API, выбор перевода книги под язык запроса |
| `backend/main/models.py` | `Book`, `BookTranslation`, `Cart`, `CartItem`, `Order`, `OrderItem` |
| `backend/main/management/commands/seed.py` | Демо-каталог, переводы, обложки, демо-пользователь |
| `frontend/src/services/api.ts` | Типизированный API-клиент, хранение JWT, общее обновление токена |
| `frontend/src/router.ts` | Ленивые маршруты, проверки авторизации, заголовки страниц |
| `frontend/src/i18n/` | Настройка vue-i18n, правила множественного числа, тексты на четырёх языках |

### Что изменилось при доработке

Сначала проект был магазином на Django с серверными шаблонами, и в заказе
могла быть только одна книга. Потом его разделили на REST API и фронтенд на
Vue. При доработке было сделано следующее.

- Удалены остатки сгенерированного шаблона, в том числе неиспользуемые
  Tailwind и PostCSS, типы React, аналитика и картинки-заглушки.
- Добавлены отмена заказа с возвратом остатков под блокировкой строк, фильтры
  каталога и корзина с постоянным числом запросов.
- API описан через OpenAPI и Swagger UI. Добавлены лимиты запросов, health
  check для docker-compose и настройки HTTPS.
- Витрина переделана. Состояние каталога хранится в URL, после входа
  пользователь возвращается на ту же страницу, количество ограничено остатком.
  Появились скелетоны загрузки, пустые состояния, страница 404, тёмная тема и
  мобильная вёрстка.
- Интерфейс, сообщения API и каталог переведены на русский, французский и
  немецкий.
- У демо-книг появились настоящие обложки.
- Тестов стало 138. В CI добавлены линтер и проверки схемы, переводов и
  покрытия.

## Запуск без Docker

Нужны Python 3.12 или новее, Node.js 20 или новее и pnpm. Если настройки
Postgres не заданы, бэкенд работает на SQLite.

```bash
./scripts/build-dev.sh          # Linux и macOS, настраивает и запускает оба приложения
.\scripts\build-dev.ps1         # Windows (PowerShell)
```

Или по шагам.

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py seed           # демо-каталог, переводы, обложки, демо-пользователь
python manage.py runserver      # http://127.0.0.1:8000

cd ../frontend
pnpm install
pnpm run dev                    # http://127.0.0.1:5173
```

Обложки демо-книг лежат в `backend/main/fixtures/covers/`, поэтому `seed`
работает без интернета. Если у книги нет сохранённой обложки, `seed` скачивает
её из Open Library. `--save-covers` сохраняет скачанное в эту папку,
`--no-covers` отключает загрузку, `--flush` начинает с пустого каталога.

## Настройки

Настройки берутся из переменных окружения. docker-compose читает их из `.env`,
пример в [`.env.example`](.env.example).

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `SECRET_KEY` | Секретный ключ Django | небезопасный ключ для разработки |
| `DEBUG` | Режим отладки | `True` (`False` в Docker) |
| `ALLOWED_HOSTS` | Разрешённые хосты через запятую | локальные хосты в режиме отладки |
| `CORS_ALLOWED_ORIGINS`, `CSRF_TRUSTED_ORIGINS` | Адреса фронтенда | сервер Vite |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_HOST`, `POSTGRES_PORT` | PostgreSQL используется, если задан `POSTGRES_DB` | SQLite |
| `SEED_ON_START` | Загружать демо-данные при старте контейнера | `1` |
| `DJANGO_SUPERUSER_USERNAME`, `DJANGO_SUPERUSER_PASSWORD`, `DJANGO_SUPERUSER_EMAIL` | Администратор, который создаётся при старте | нет |
| `HTTPS` | Secure-cookies, HSTS, редирект на HTTPS | `False` |
| `THROTTLE_ANON`, `THROTTLE_USER`, `THROTTLE_AUTH` | Лимиты запросов | `120/min`, `600/min`, `20/min` |
| `LOG_LEVEL` | Уровень логов | `INFO` |

## Тесты

```bash
cd backend
ruff check . && ruff format --check .
coverage run manage.py test && coverage report

cd ../frontend
pnpm run type-check
pnpm run coverage
```

На бэкенде 60 тестов, покрытие 94%. Они проверяют API, модели, оформление и
отмену заказов, фильтры, переводы, число SQL-запросов, лимиты и команду
`seed`. На фронтенде 78 тестов, покрытие 92%. Они проверяют страницы,
проверки в роутере, API-клиент, компоненты и переводы. Ещё CI ищет
несозданные миграции, проверяет схему OpenAPI и скомпилированные переводы и
собирает Docker-образы.

Скриншоты на всех языках снимаются с запущенного приложения командой
`cd frontend && BASE_URL=http://localhost:8080 pnpm run screenshots`.

## Ограничения

Что пока не сделано.

- Нет платёжного сервиса. Оформление создаёт заказ в статусе «Ожидает», дальше
  его ведут сотрудники в админке.
- Переводы есть только у демо-книг. Новая книга показывается на английском,
  пока в админке не добавят перевод.
- Все цены в долларах США.
- JWT хранится в `localStorage`. Cookie с флагом httpOnly лучше защищает от
  XSS, но требует защиты от CSRF.
- Поиск работает через `icontains`. Для большого каталога понадобится
  полнотекстовый поиск PostgreSQL.
