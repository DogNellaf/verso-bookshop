## Коротко

**Verso** — fullstack интернет-магазин книг: REST API на Django REST Framework,
витрина на Vue 3 + TypeScript, PostgreSQL, Docker. Покупатель ищет книги,
кладёт их в корзину, оформляет и отслеживает заказы; администратор управляет
каталогом и заказами через Django-админку.

- **Роль:** fullstack-разработка — проектирование БД и API, фронтенд, DevOps, тесты
- **Стек:** Python 3.12, Django 5, DRF, SimpleJWT, PostgreSQL · Vue 3, TypeScript, Vite · Docker Compose, nginx, gunicorn, GitHub Actions
- **Код:** [github.com/DogNellaf/verso-bookshop](https://github.com/DogNellaf/verso-bookshop)
- **Запуск:** `docker compose up --build` → http://localhost:8080, кнопка «Use demo account»

## Задача

Сделать магазин, который ведёт себя как настоящий, а не как учебный CRUD:

1. Корректно работать с остатками — нельзя продать книгу, которой нет,
   даже если два человека нажали «Оформить» одновременно.
2. Хранить историю заказов неизменной, даже когда цены и каталог меняются.
3. Дать удобную витрину: поиск, сортировка, фильтры, корзина, которая
   сохраняется между сессиями, понятные ошибки, мобильная версия.
4. Запускаться одной командой и быть задокументированным для других
   разработчиков.

## Решение

### Backend: целостность данных

- **Атомарный checkout.** Оформление заказа — одна транзакция: строки книг
  блокируются `SELECT … FOR UPDATE`, остатки проверяются и списываются, корзина
  очищается. Если хотя бы одной позиции не хватает, откатывается всё, а
  пользователь видит, каких книг и сколько осталось.
- **Снимок цены.** Строка заказа хранит название и цену на момент покупки,
  связь с книгой — `SET_NULL`. Поменяли цену или удалили книгу — история
  заказов не изменилась.
- **Отмена заказа** возвращает книги на склад в той же транзакции и работает
  только для заказов в статусе «ожидает» — повторная отмена не удвоит остатки.
- **Производительность.** Корзина с позициями и книгами загружается одним
  JOIN вместо N+1 запросов; количество запросов закреплено тестом.
- **Безопасность.** JWT с ротацией refresh-токенов, rate limiting на вход и
  регистрацию, валидация паролей, защита от open redirect, настройки HTTPS
  (secure cookies, HSTS) включаются одной переменной.
- **Документация API.** OpenAPI 3 + Swagger UI на `/api/docs/`; схема
  проверяется в CI, так что документация не расходится с кодом.

### Frontend: витрина

- **Состояние каталога в URL.** Поиск, сортировка, фильтр «в наличии» и номер
  страницы — query-параметры. Ссылкой можно поделиться, перезагрузка и кнопка
  «назад» работают как ожидается.
- **Авторизация без сюрпризов.** Защищённые страницы отправляют на вход и
  возвращают обратно; access-токен обновляется незаметно, а параллельные
  запросы делят один refresh, а не устраивают гонку.
- **Внимание к деталям:** выбор количества ограничен остатком, бейдж
  «Осталось N», скелетоны загрузки, пустые состояния, подтверждение отмены,
  подсветка только что оформленного заказа.
- **Светлая и тёмная темы** на CSS-переменных, без UI-фреймворка; тема берётся
  из настроек ОС и запоминается.
- **Генерируемые обложки.** Если у книги нет картинки, рисуется типографская
  обложка с цветом, вычисленным из названия, — интерфейс выглядит законченным
  даже офлайн, без сторонних сервисов-заглушек.
- **Доступность:** skip-link, подписи у всех элементов управления, видимый
  фокус, учёт `prefers-reduced-motion`.

### Инфраструктура

- Docker Compose: PostgreSQL, Django на gunicorn, nginx раздаёт SPA и
  проксирует API с одного origin — CORS в продакшене не нужен.
- Health-check'и: nginx стартует только когда backend готов, backend — когда
  готова БД. При первом запуске применяются миграции и загружаются демо-данные.
- GitHub Actions: ruff, проверка миграций, валидация OpenAPI-схемы, тесты
  backend и frontend, type-check, сборка Docker-образов.

## Результат

- **115 автотестов:** 46 на backend (API, модели, конкурентный checkout,
  отмена заказов, фильтры, число SQL-запросов, rate limiting) и 69 на frontend
  (страницы, роутер и guard'ы, API-клиент, компоненты).
- Запуск всего стека с демо-данными — одна команда; демо-аккаунт входит в
  один клик.
- Документированный API, адаптивная витрина со светлой и тёмной темой,
  админка для управления каталогом и заказами.
